# M3 — Retrieval over the policy

## What we built
- Structure-aware chunker: one `###` rule section per chunk with its rule IDs (`retrieval/index.py::chunk_policy`).
- BM25 (`rank-bm25`), dense (`fastembed`, `BAAI/bge-small-en-v1.5`), and hybrid via reciprocal rank fusion.
- `search_policy` tool returning passages with rule IDs and section titles.
- `evals/retrieval_qa.yaml` (25 questions) and `evals/retrieval_eval.py` → `results/retrieval.json`.
- BM25 fallback when the embedding model can't load.

**Why this design.** Rule IDs and terms like "COD" are lexical; customer phrasing ("phone came broken") is semantic.
RRF combines rankings without calibrating score scales. Alternative: a vector DB — unnecessary for ~32 chunks.

## Key concepts
- **RRF**: score(d) = Σ over rankers of 1 / (60 + rank). Rank-based, so BM25's unbounded scores and cosine
  similarities don't need normalising.
- **Metrics**: recall@k = fraction of questions whose expected rule is in the top k; MRR = mean of 1/rank of the first hit.
- **Strict hit definition**: only a chunk whose *heading* rule ID matches counts; worked examples don't.
- **Agentic retrieval**: the prompt has a compact summary; the model calls `search_policy` when unsure.

- `make eval-retrieval` and open `results/retrieval.json`.
- `uv run python -c "from trustdesk.retrieval import build_index; [print(p['rule_ids'], p['title']) for p in build_index().search('refund COD to new upi')]"`

## Interview questions
1. **Why hybrid retrieval?** Lexical and semantic retrievers fail differently: BM25 misses paraphrases, dense models
   blur exact identifiers. Fusing ranks gets the union of their strengths; on our 25 questions hybrid's recall@4 beat
   both (see the results file). With a tiny corpus this is cheap.
2. **Why chunk by rule section?** Policy answers are rule-scoped; a chunk that spans two rules dilutes both, and
   tagging chunks with rule IDs lets the agent cite precisely. Fixed-size chunks would split tables and examples.
3. **How do you know the retrieval eval isn't overfit?** I wrote the questions before measuring, didn't tune on
   them, and report all three methods. With n=25 the numbers are noisy; a held-out set and more paraphrases would be
   the next step.
