# M7 — Security

## What we built
- `docs/THREAT_MODEL.md`: assets, actors, trust boundary, OWASP agentic/LLM mapping, lethal-trifecta analysis.
- Defense levels D0–D3 wired through prompts, tools and graph.
- 10 attack tasks: review, delivery note, ticket history, direct social engineering, pasted fake system notice.
- Deterministic attack goal checks (DB rows, literal output, write-before-verification).
- `docs/RED_TEAM_LOG.md` template for your manual attacks.

**Why this design.** Each layer cuts a different leg: spotlighting lowers the model's susceptibility; code
enforcement makes money/identity violations impossible; masking removes private data before the model sees it;
approval puts a human on the residual high-risk actions. The ablation measures each layer's marginal value.

## Key concepts
- **Indirect vs direct injection**: text the agent *reads* (reviews) vs text the user *types*.
- **Spotlighting** (`security/spotlight.py`): delimit + datamark (`ˆ` for spaces) + neutralise closing tags.
- **Enforcement beats persuasion**: at D2 the attacker's UPI can't be a refund destination because
  `check_refund` only accepts verified UPIs — whatever the model "decides".
- **Utility under attack**: the attack tasks also contain a legitimate request; a paranoid agent that refuses
  everything fails them.

## Interview questions
1. **What is the lethal trifecta and how does TrustDesk handle it?** Private data + untrusted content + an
   exfiltration channel. Untrusted content is unavoidable (reviews), so we cut the others: masking and identity
   gates mean the model rarely holds other people's data, and money can't flow to attacker-chosen destinations
   because destinations come from the database. The chat reply remains a channel, which is why data is cut at source.
2. **Why isn't spotlighting enough?** It's a probabilistic defense: it changes how likely the model is to follow
   injected text, and adaptive attacks can still win. It's valuable for utility under attack (the agent keeps helping
   the real customer), but invariants need code.
3. **How would you show defense in depth quantitatively?** Run the same tasks at D0–D3 and with a rubber-stamp
   approver at D3. If ASR stays near zero with rubber-stamping, the engine — not the human — is carrying the money
   invariants, and the human's value shows up in the hitl tasks instead.
