# M2 — Agent core (LangGraph graph, model adapter, prompts, CLI)

## What we built
- `agent/graph.py`: nodes `agent`, `tools`, `approval_gate`, `finalize`; loop detection, max steps, refusal handling.
- `agent/model.py`: `ChatModel` protocol; Ollama (native API), local OpenAI-compatible, scripted and cached adapters.
- `agent/prompts.py`: role + policy summary + workflow + untrusted-content rules; constant per defense level.
- `agent/runtime.py::Conversation`: `send()` / `resume()` / `pending_approval()` over a graph thread.
- `trustdesk chat` CLI and `agent/demo_model.py::RuleBasedDemoModel` for no-key demos.

**Why this design.** A custom model node (not `langchain-ollama`) because we need Ollama's native options —
`num_ctx` (otherwise the prompt's front, i.e. the policy, is silently truncated) and `think` — and a provider-neutral,
append-only message format that tests can script. Alternative: LangGraph's prebuilt ReAct agent — rejected because the approval gate and loop detection
need custom nodes anyway.

## Key concepts
- **Append-only messages**: `messages: Annotated[list, operator.add]` — nodes return *new* messages; nothing is
  edited, so history is auditable and Ollama can reuse its KV cache for the unchanged prefix.
- **Content blocks by type**: one provider-neutral message shape (`text`, `tool_use`, `tool_result` blocks);
  `OllamaModel.to_ollama` translates at the edge and strips any `<think>` text from replies.
- **Routing**: `after_agent` (tools / finalize / END) and `after_tools` (approval_gate / finalize / agent).
- **Loop detection**: `call_counts[signature]` where signature = tool name + sorted JSON args; the 3rd identical call
  ends the turn with an escalation.
- **Closures, not state**: `build_graph(env, model, …)` — the DB and model aren't serialisable, so nodes close over them.

## Interview questions
1. **Why keep the system prompt constant within a conversation?** A stable prefix lets the inference server reuse
   its KV cache (Ollama reports `prompt_eval_cached_count`), which matters a lot for latency on a laptop, and it
   keeps behaviour predictable turn to turn. Some hosted APIs also bind reasoning blocks to the exact prefix. So
   per-session facts go into tool results, and permissions are enforced in tools rather than by changing the tool list.
2. **How do you stop an agent from looping forever?** Two guards: a per-turn step budget (`max_steps`, default 25) and
   identical-call detection (same tool + args 3 times). Both route to `finalize`, which escalates to a human and
   replies gracefully, rather than raising.
3. **How do you test an LLM agent without calling the LLM?** Script the model: `ScriptedModel` emits fixed tool-call
   sequences, so the graph, tools, routing and persistence are tested deterministically. Model quality is measured
   separately by the eval harness.
